각자의 AI에서 완성할 결과

자기 계정으로 자료를 등록하고 최소 6번 질문합니다. 첫 답과 수정한 답, 조건이 빠진 자료와 완전한 자료의 차이, 구버전 포함/제외 결과, 근거 부족 응답을 직접 저장합니다. 교재는 파일과 질문을 제공하며 답변은 본인의 AI에서 만듭니다.

자기 AI 실습자료 ZIP ↓실행·비교 기록지 ↓실행 질문 전체 ↓
실습 환경: NotebookLM을 기본 경로로 사용합니다. 평소 쓰는 다른 AI도 파일 첨부 또는 텍스트 붙여넣기로 참여할 수 있습니다. NotebookLM의 소스 선택·인용과 일반 채팅의 입력자료 지정은 구분합니다. 내부 검색 설정을 확인하지 못한 실습을 “RAG 시스템 구축 완료”로 기록하지 않습니다.

도구에 따라 준비하는 방법

내가 사용하는 환경자료를 넣고 비교하는 방법
NotebookLM · 기본새 노트북 → 파일 또는 복사된 텍스트로 자료 추가 → 사용할 소스 선택 → 질문 → 인용 클릭
내가 사용하는 다른 AI새 대화 → 파일 첨부 기능이 있으면 TXT 첨부, 없으면 본문 붙여넣기 → 질문 → 자료 ID와 원문 대조
파일을 제외하거나 교체할 수 없는 환경새 노트북/새 대화를 만들고 비교 조건의 자료만 다시 넣기. 이전 답변이 섞이지 않게 하기

파일 첨부·소스 선택 메뉴와 사용 한도는 계정에 따라 다릅니다. 도구가 자료 전체를 입력으로 읽었는지 검색해 읽었는지 확인할 수 없다면, 기록지에 “내부 방식 미확인”이라고 적습니다.

1

자기 AI에 자료 넣기 · 10분

ZIP을 풀고 01_EDU-01_2026.txt부터 05_EDU-05_2026.txt까지 현재 자료 5개를 넣습니다. NotebookLM에서는 출처 추가로 개별 등록하고 모두 선택합니다. 다른 AI에서는 새 대화에 5개를 첨부하거나 00_CURRENT_ALL.txt의 본문을 붙여넣습니다.

예상 상태
본인 계정에 자료가 등록되거나 대화에 제공됩니다.
직접 확인
EDU-01~05 ID와 실제 본문을 직접 확인합니다. AI에게 읽었다는 대답만 받는 것으로 끝내지 않습니다.
막혔을 때
파일을 못 읽으면 원문을 복사한 텍스트로 넣습니다. 도구 접속이 불가하면 짝의 화면에서 검증 역할을 맡되 개인 실행 완료로 기록하지 않습니다.

자료는 교육용 가상 자료 열람 규칙입니다. HUG 규정이나 법령이 아닙니다. 뒤의 A/B/C에서는 기존 공개 법령·판례·블로그 자료를 본인의 AI로 다룹니다.

2

기본 질문과 근거 요구 질문 비교 · 10분

아래 두 질문을 순서대로 본인의 AI에서 실행합니다. 답변을 기록지에 복사하고 승인 조건·자료 ID·원문 문장이 달라진 부분을 표시합니다.

예상 상태
두 응답이 저장되고, 결론이 같은 경우에도 근거와 검증 가능성을 비교할 수 있습니다.
직접 확인
EDU-01·03과 답변을 대조합니다. 기본 질문도 잘 답할 수 있으며 일부러 틀린 결과를 만들어내지 않습니다.
막혔을 때
인용이 없으면 자료 ID와 해당 원문 문장을 요청합니다. 원문에 없는 문장을 인용처럼 제시했다면 직접 표시하고 수정합니다.
내 AI에서 실행 1 · 기본 질문
이번에 선택하거나 제공한 교육자료만 사용해 답해줘. 교육자료 열람을 신청하면 바로 자료를 내려받을 수 있어? 먼저 두 문장으로 답해줘.
내 AI에서 실행 2 · 조건과 근거 지정
이번에 선택하거나 제공한 교육자료만 사용해 답해줘. 교육자료 열람을 신청하면 바로 내려받을 수 있는지, 신청 접수와 담당자 승인을 구분해 설명해. 표의 열은 결론 / 적용 조건 / 자료 ID / 결론을 뒷받침하는 원문 문장으로 구성해. 원문에 없는 사실은 추가하지 마. 판단에 필요한 내용이 빠졌다면 확인 필요로 표시해. 네가 만든 인용문은 실제 자료의 해당 문장과 일치해야 해.
3

조건이 빠진 자료와 완전한 자료 비교 · 10분

새 노트북 또는 새 대화 A에 07_EDU-03_PARTIAL.txt만 넣고 실행 2 질문을 합니다. 새 노트북 또는 새 대화 B에는 03_EDU-03_2026.txt만 넣고 같은 질문을 합니다. 두 결과와 원문을 나란히 기록합니다.

예상 상태
불완전한 자료에는 접수/승인 구분이 없고 완전한 자료에는 있습니다. 모델의 답변이 이 차이를 드러내는지 검사합니다.
직접 확인
원문에서 빠진 조건을 AI가 일반 지식으로 채웠는지 확인합니다. 이것은 자료 단위 비교이며 내부 청크 크기를 직접 바꾼 실험이 아닙니다.
막혔을 때
A에 완전한 자료나 이전 대화가 섞였다면 비교용 새 공간에서 다시 실행합니다. 조건을 못 찾는 답도 실패 위치를 기록하면 활동 결과입니다.
4

표현 변경과 버전 충돌 비교 · 15분

현재 자료 5개가 있는 본래 노트북/대화로 돌아와 실행 3을 묻습니다. 원문의 “예약 변경”을 다른 표현으로 물어도 근거를 찾는지 봅니다. 이어 06_EDU-OLD_2025.txt를 더해 실행 4를 합니다. 구버전 소스를 해제하거나 새 대화에 현재 자료만 넣고 실행 5를 합니다.

예상 상태
표현이 달라도 EDU-02의 조건을 찾는지, 2025 이메일 안내와 2026 신청 화면 안내를 구분하는지 관찰합니다.
직접 확인
답이 맞더라도 의미 검색/벡터 검색이 사용됐다고 단정하지 않습니다. 소스를 실제 제외한 것과 지시문에서 제외하라고 한 것을 별도로 기록합니다.
막혔을 때
소스 선택 기능이 없으면 현재 자료만 제공한 새 대화로 비교합니다. 구버전 제외를 지시만 했다면 “지시문으로 범위 지정”이라고 기록합니다.
내 AI에서 실행 3 · 다른 표현으로 질문
이번에 선택하거나 제공한 자료만 사용해, 교육자료를 볼 일정을 다른 시간으로 바꾸려면 어떻게 해야 하는지 설명해. 원문에서 사용하는 표현이 무엇인지도 적어줘. 변경 시점별 조건 / 자료 ID / 원문 문장을 함께 제시해. 찾지 못하면 찾지 못했다고 말해.
내 AI에서 실행 4 · 버전 충돌
제공한 자료 중 2025 버전과 2026 버전의 교육자료 열람 신청 방법을 비교해. 버전 / 신청 경로 / 원문 근거 / 서로 다른 내용의 표로 작성해. 자료에 없는 개정 이유나 시행일은 추정하지 마. 내가 어떤 버전을 기준으로 업무를 처리할지 지정하지 않았다면 먼저 기준 버전을 확인해.
내 AI에서 실행 5 · 현재 자료만 사용
이번에 선택하거나 제공한 2026 자료만 사용해 교육자료 열람 신청 방법을 답해줘. 신청 화면과 담당자 승인 조건을 구분해. 자료 ID와 원문 문장을 제시하고, 제외한 2025 안내의 이메일 방식이 섞이지 않았는지 확인해.
5

근거 밖 질문·새 문의·저장 · 10분

실행 6으로 자료에 없는 기간과 금액을 묻습니다. 시간이 남으면 실행 7의 새 문의에 재사용합니다. 자신의 응답을 TXT·문서로 저장하고 짝이 원문을 대조합니다.

예상 상태
확인 불가와 추가 자료가 분리된 응답, 실제 실행 기록이 남습니다.
직접 확인
없는 숫자를 답했다면 오류로 남깁니다. 답을 고친 뒤 원문에서 뒷받침되는 부분과 여전히 없는 부분을 구분합니다.
막혔을 때
수치가 만들어졌다면 “그 숫자를 뒷받침하는 원문 문장을 제시하고 없으면 철회해”라고 요청하고 다시 검증합니다.
내 AI에서 실행 6 · 자료 밖 질문
이번에 선택하거나 제공한 자료만 사용해 답해줘. 이 교육자료 열람 신청의 처리 기간은 며칠이며, 자료에 없는 출장비 지급액은 얼마야? 항목별로 자료에서 확인되는 내용 / 확인 불가한 내용 / 추가로 필요한 자료를 나눠 적어줘. 숫자를 추정하지 마.
선택 실행 7 · 다른 조건의 문의에 재사용
교육용 가상 새 문의야. 열람 예약 시작 시각이 이미 지났는데 예약을 바꾸고 싶어. 이번에 선택하거나 제공한 자료를 근거로 안내 초안 3문장을 작성해. 시작 전과 시작 이후 조건을 구분하고 담당자에게 확인할 내용을 붙여줘. 자료 ID와 원문 근거도 남겨줘.

내 결과를 판단하는 기준

항목원문 대조 기준
신청/승인신청 접수만으로 승인된 것으로 보지 않음
예약 변경시작 전 요청과 시작 이후 담당자 확인 구분
버전2025 이메일 방식과 2026 신청 화면 방식 구분
자료 밖 질문제공 자료에 정확한 기간·출장비 지급액 없음
인용ID뿐 아니라 원문 문장이 주장을 뒷받침해야 함
예상 결과는 비교 기준이며 새 질문의 AI 응답을 미리 실행한 캡처는 아닙니다. 응답은 계정·도구·대화 상태에 따라 달라질 수 있습니다. 정답처럼 보이는 문장을 복사하는 대신 자신의 실제 결과와 원문을 제출합니다.

스스로 확인하기

먼저 답을 생각한 뒤 해설을 펼치세요.

1. 문서 하나를 두 파일로 나누면 내부 청킹을 제어한 것인가요?

아니요. 사용자가 제공하는 자료 단위를 바꾼 것입니다. 서비스 내부의 청크·검색 설정은 별도로 확인해야 합니다.

2. 다른 표현의 질문에도 답하면 벡터 검색이 사용됐다는 증거인가요?

그 결과만으로 내부 방식을 알 수 없습니다. 관찰한 답과 사용한 자료를 기록합니다.

3. 자료에 없는 기간을 그럴듯하게 답하면 통과인가요?

아니요. 기간을 지지하는 원문이 없으면 확인 불가로 고치고 추가 자료를 요청합니다.
