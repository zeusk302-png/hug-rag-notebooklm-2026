02 · 검색 조각을 직접 관찰하기

청크 경계·검색 표현·버전·전달 근거를 바꿔 봅니다. 중간 결과를 보고 사람이 답을 검증합니다.

완성할 것: 청크 비교표와 검색 실험 기록준비 · 먼저 원문 전체 읽기조건과 결론을 함께 자르기 · 10분같은 자료에서 검색어 바꾸기 · 15분버전 필터와 조각 수 바꾸기 · 15분근거에서 답변을 작성하고 반례 찾기 · 10분기록 저장·역할 바꾸기 · 5분기준 예시 · 먼저 활동한 뒤 펼치세요.스스로 확인하기
이번에는 검색의 중간 결과를 직접 봅니다. 아래 도구는 이 페이지에서 실행하는 단순 키워드 검색입니다. 임베딩·BM25·재정렬 모델·언어모델은 사용하지 않습니다. 자료는 전부 새로 만든 교육용 가상 자료 열람 규칙이며 HUG 규정이나 법령이 아닙니다. 어떤 조각이 선택되어 생성 입력에 들어가는지 관찰하는 활동입니다.

완성할 것: 청크 비교표와 검색 실험 기록

2인 1조로 검색 담당과 검증 담당을 정합니다. 도구 결과를 본 뒤 역할을 바꿉니다. 자료 읽기 → 청크 경계 정하기 → 검색하기 → 전달 근거 확인 → 사람이 답변 작성 순서로 진행합니다.

준비 · 먼저 원문 전체 읽기

ID / 버전가상 원문
EDU-OLD / 2025교육용 자료 열람 신청은 담당자에게 이메일로 제출한다.
EDU-01 / 2026교육용 자료 열람 신청은 신청 화면으로 제출한다. 승인 전에는 자료를 내려받을 수 없다.
EDU-02 / 2026교육용 자료 열람 예약 변경은 열람 시작 전까지 신청 화면에서 요청한다. 시작 이후에는 담당자 확인이 필요하다.
EDU-03 / 2026담당자가 교육용 자료 열람을 승인한 경우 자료를 내려받을 수 있다. 신청 접수만으로 승인된 것으로 보지 않는다.
EDU-04 / 2026교육용 자료의 오류 신고에는 자료 ID와 잘못된 부분을 함께 적는다. 담당자가 원문을 대조한다.
EDU-05 / 2026교육용 자료에 없는 비용과 처리 기간은 담당자 확인이 필요하다. 임의로 추정하지 않는다.
1

조건과 결론을 함께 자르기 · 10분

EDU-03을 읽고 “자료를 내려받을 수 있다”만 남긴 조각과, 승인 조건·접수의 한계까지 포함한 조각을 각각 활동지에 적습니다. 두 조각으로 “신청만 하면 다운로드 가능한가?”에 답해 보세요.

예상 상태
짧게 자른 조각에서는 승인 조건을 놓칠 수 있다는 차이가 드러납니다.
직접 확인
좋은 청크에 승인 조건과 접수/승인의 구분이 함께 있는지 확인합니다.
막혔을 때
두 방식이 같아 보이면 조건을 지운 조각만 파트너에게 보여주고 답하게 합니다. 원문으로 돌아가 빠진 문장을 표시합니다.
2

같은 자료에서 검색어 바꾸기 · 15분

아래 입력에 “예약 변경”을 넣어 검색합니다. 결과 ID·점수·전달 근거를 적습니다. 다음에는 “일정 바꾸기”로 검색합니다. 자료가 같은데 왜 결과가 달라지는지 이야기하세요.

예상 상태
“예약 변경”은 EDU-02를 찾습니다. “일정 바꾸기”는 대응하는 표현이 없어 결과가 없습니다.
직접 확인
점수는 입력한 단어 중 원문에 포함된 단어의 수입니다. 의미 유사도나 정답 확률로 해석하지 않습니다.
막혔을 때
결과가 없으면 입력을 “예약 변경”으로 되돌립니다. 동의어 버튼은 없으며, 사람이 표현을 바꿨다는 점을 기록합니다.

검색 조각 관찰 도구

검색 결과 보기를 눌러 시작하세요.

생성 단계에 전달할 입력

검색 결과로 조립한 입력 텍스트입니다. AI가 작성한 답변이 아닙니다.

검색 후 여기에 질문과 근거가 표시됩니다.
3

버전 필터와 조각 수 바꾸기 · 15분

검색어를 “신청”으로 바꿉니다. 유효 자료 체크를 끄고, 조각 수를 6개로 검색합니다. 2025 자료의 이메일 안내와 2026 자료의 신청 화면 안내가 함께 있는지 봅니다. 체크를 켜서 재검색한 뒤, 조각 수 1개와 3개를 각각 비교합니다.

예상 상태
버전 필터를 켜면 EDU-OLD가 빠집니다. 조각 수를 바꾸면 전달 근거 범위가 달라집니다.
직접 확인
후보 전체와 실제 전달된 조각을 구분합니다. 많아진 조각 중 질문에 필요 없는 것도 표시합니다.
막혔을 때
변화가 없으면 검색 후 다시 실행했는지 확인합니다. 옵션을 바꾸는 것만으로 기존 결과가 자동 변경되지는 않습니다.
4

근거에서 답변을 작성하고 반례 찾기 · 10분

검색어를 “승인”으로 바꾸고 결과를 봅니다. 사람 손으로 답 2문장을 적고 EDU-03을 인용합니다. 다음에는 “출장비 지급”을 검색하고 같은 방식으로 답을 쓸 수 있는지 확인합니다.

예상 상태
승인/접수 구분과 근거 ID가 남습니다. 출장비에는 근거 부족이라고 적습니다.
직접 확인
자연스러운 문장보다 근거가 있는지 먼저 봅니다. 검색 없음은 업무가 존재하지 않는다는 증명이 아닙니다.
막혔을 때
빈 결과를 보완하려고 수치를 만들지 않습니다. 자료 부족·검색 표현 불일치 중 어느 가능성이 있는지 활동지에 적습니다.
5

기록 저장·역할 바꾸기 · 5분

TXT 저장 버튼으로 마지막 결과를 저장합니다. 활동지에는 실험 4번의 기록을 남깁니다. 파트너가 검색한 결과와 작성한 답의 근거가 일치하는지 검토합니다.

예상 상태
청크 2종 비교와 검색 실험 4행, 사람이 작성한 답/보류 문장이 남습니다.
직접 확인
저장한 파일을 열어 질문·옵션·후보·전달 근거가 있는지 확인합니다.
막혔을 때
저장이 막히면 표시된 결과와 전달 입력을 활동지에 복사합니다. 페이지를 새로고침하면 결과가 초기화됩니다.

기준 예시 · 먼저 활동한 뒤 펼치세요.

4가지 실험의 확인 기준

① 예약 변경: EDU-02가 두 단어를 포함하여 점수 2. ② 일정 바꾸기: 결과 없음. ③ 신청 / 모든 버전: EDU-OLD가 후보에 포함되며 유효 자료만 설정에서는 제외. ④ 출장비 지급: 결과 없음. 점수 동점은 자료 ID 순입니다. 이 도구의 순위를 실제 검색 엔진의 성능으로 해석하지 않습니다.

스스로 확인하기

먼저 답을 생각한 뒤 해설을 펼치세요.

1. 단어 검색에서 결과가 없으면 문서에도 답이 없나요?

표현이 다르면 놓칠 수 있습니다. “일정 바꾸기”의 뜻과 “예약 변경”의 원문 표현을 대조합니다.

2. 이 도구의 전달 조각 3개가 NotebookLM의 Top-k인가요?

아니요. 이 페이지가 실행한 단순 검색의 설정이며 NotebookLM 내부 설정은 확인하지 않았습니다.

3. 키워드 검색을 실행했으므로 전체 RAG가 완성됐나요?

아니요. 생성 모델 연결·실제 권한·갱신·검증·운영은 별도입니다. 여기서는 근거 검색과 입력 조립을 관찰했습니다.
