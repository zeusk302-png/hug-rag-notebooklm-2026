개인 연결 사전 준비 — Windows / 강사 확인 후 실행

이 추가 실행기는 강사 PC에서 실제 실행한 코드의 경로 설정만 개인 폴더 기준으로 바꾼 버전입니다. 학생 Team 환경·모든 OS에서 검증한 것은 아닙니다. 기본 수업은 자기 Claude Code와 로컬 로그로 진행할 수 있습니다. Langfuse는 강사 시연을 읽고, 개인 프로젝트가 준비된 사람만 직접 연결합니다.

1. Python 3.12와 로그인된 Claude Code를 준비합니다. claude --version과 claude auth status를 확인합니다. 개인 플랜 가입이 설치·기관 도구 권한을 자동 부여하지는 않습니다.
2. 새 실습 폴더에서 다음을 실행합니다. 기존 업무 폴더에 전역 후크를 설치하지 않습니다.
   py -3.12 -m venv .venv
   .venv\Scripts\python.exe -m pip install notebooklm-mcp-cli==0.15.6 -r requirements.txt
   $env:NOTEBOOKLM_MCP_CLI_PATH = "$PWD\.runtime\notebooklm-auth"
   .venv\Scripts\nlm.exe login --profile hug-training --storage protected
   MCP 전용으로 열린 Chrome에서 본인이 Google 로그인합니다. 비밀번호·쿠키를 채팅으로 보내지 않습니다. 기존 Chrome에 로그인했더라도 이 인증이 별도로 필요할 수 있습니다.
3. example JSON 세 파일을 각각 notebooks.json, source-registry.json, mcp-config.json으로 복사합니다. YOUR 값을 모두 본인 값으로 바꾸고 MCP 실행 파일·인증 폴더 경로를 실제 절대경로로 고칩니다. 노트북은 A/B/C 세 개, 소스는 표본 질의용 지정 문서 세 개입니다. 노트북 전체에는 각각 45개가 있어야 합니다.
4. 강사와 함께 notebook_get으로 본인 노트북의 소스 이름과 source_id를 확인합니다. 공개 목록의 L276291 같은 문서 ID와 서비스가 부여한 source_id는 다른 값입니다. 이름만 같다고 다른 파일을 연결하지 않습니다. source-registry에는 본인 UUID와 공식 URL을 넣습니다.
5. 01_harness-instruction.txt를 CLAUDE.md로 복사하고 본인 지침으로 수정합니다. 실행기는 지침과 plan.json을 읽도록 Claude Code에 요청합니다. 설치·인증 파일을 근거 소스로 올리지 않습니다.
6. 본인 Langfuse 프로젝트에서 전송 전용 키를 만들고 .runtime/langfuse.env에 직접 저장합니다. 파일 예시(실제 값은 이 문서에 쓰지 않음):
   LANGFUSE_PUBLIC_KEY="YOUR_PUBLIC_KEY"
   LANGFUSE_SECRET_KEY="YOUR_SECRET_KEY"
   LANGFUSE_BASE_URL="YOUR_PROJECT_REGION_BASE_URL"
   프로젝트 리전의 주소를 사용합니다. 키는 수업 뒤 폐기 또는 만료 관리합니다. 계정 약관과 조직 데이터 전송 정책은 본인이 확인합니다. 내부 문서·고객정보로 실행하지 않습니다.
7. 실행: .venv\Scripts\python.exe run-langfuse.py
   예상: LANGFUSE_TRACE_STARTED → 실제 QUERY_RESULT → DONE. langfuse 하위 새 실행 폴더에 trace.json, 실제 응답, review.md, check.md가 생깁니다. trace.json의 URL을 브라우저로 열어 실제 기록이 도착했는지 확인합니다. flush나 파일 존재만으로 Cloud 수신을 단정하지 않습니다.
8. A 최초 호출은 timeout=0.001의 의도적 장애 시험입니다. A 재시도60초, B/C 실제 조회, 인용 검사, 결과 작성이 이어집니다. 45개 전체 검색 부하 시험은 아닙니다. SDK4.18.0에 맞춘 예제이므로 버전을 임의로 바꾸면 API 호환성을 다시 확인합니다.
9. 인증 실패: 프로젝트·리전·키를 로컬에서 확인합니다. NotebookLM 인증 만료: 전용 로그인 재진행. 시간 초과: 질문·소스 범위를 좁히고 실패한 호출만 재시험. 인용0: 답변 문장이 있어도 보류. 키·쿠키·인코딩된 인증 헤더가 포함된 화면은 교재나 보고서에 캡처하지 않습니다.

관측 범위: Claude Code stream-json의 도구 호출/반환과 Write/Edit만 전송합니다. 모델의 숨은 사고는 전송하지 않습니다. NotebookLM 내부 검색 순위·모델별 정확한 과금·모든 로컬 동작이 보이는 것은 아닙니다. 오류를 찾는 화면이며 법적 정확도 인증이 아닙니다.
